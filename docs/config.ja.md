# 設定

[English](config.md) | 日本語

英語版（[config.md](config.md)）が正本です。食い違いがあれば英語版に従ってください。

misao は、任意の JSON ファイル `misao.json` 1 つと、いくつかの環境変数で設定します。
すべての `misao` コマンドがこのファイルを読みます。`misao serve` は起動時にデーモン関連のキーを適用するため、
`scrollback`、`rings`、`logLevel`、`socket` を変更したときはデーモンの再起動が必要です。`keys`
セクションは CLI の呼び出しごとに読まれます。

関連文書: [プロトコル](protocol.ja.md)、[CLI](cli.ja.md)、[組み込み（Node SDK）](embedding.ja.md)。

## 設定ファイルの探索

最初に見つかったファイルが使われます。ファイルは**マージされません**。どれも存在しない場合は既定値が適用されます。

| 順序 | 取得元 | ファイルがない場合 |
|---|---|---|
| 1 | `--config PATH` | エラー |
| 2 | `$MISAO_CONFIG`（空の値は未設定として扱う） | エラー |
| 3 | `$MISAO_DIR/misao.json`（`$MISAO_DIR` が設定されている場合のみ） | 次の候補へ |
| 4 | `~/.misao/misao.json` | 既定値 |

明示的に指定したファイル（1 と 2）が存在しない場合はエラーになるため、タイプミスが黙って
無視されることはありません。`$MISAO_DIR` は絶対パスか `~/` で始まるパスでなければなりません。存在するのに
読み取れないファイルは、常にエラーです。

## スキーマ

```json
{
  "keys": { "prefix": "C-^", "detach": "d", "next": "n", "prev": "p", "list": "l" },
  "scrollback": 5000,
  "rings": { "rawBytes": 1048576, "linesBytes": 4194304, "events": 1000 },
  "socket": "~/.misao/misao.sock",
  "logLevel": "info"
}
```

すべてのキーは省略可能です。

| キー | 型 | 既定値 | 説明 |
|---|---|---|---|
| `keys.prefix` | string | `"C-^"` | `misao attach` のプレフィックスキー。コントロールキーのみ: `C-<char>` で、`<char>` は `@ A-Z [ \ ] ^ _` のいずれか（大文字小文字を区別しない）。`C-[`（ESC）は拒否されます。 |
| `keys.detach` | string | `"d"` | プレフィックスの次のキー: `attach` を抜ける（ペイン一覧へ戻る）。 |
| `keys.next` | string | `"n"` | プレフィックスの次のキー: 次のペイン。 |
| `keys.prev` | string | `"p"` | プレフィックスの次のキー: 前のペイン。 |
| `keys.list` | string | `"l"` | プレフィックスの次のキー: ペイン一覧を表示する。 |
| `scrollback` | integer >= 1 | `5000` | 各ペインの画面モデルのスクロールバック行数。 |
| `rings.rawBytes` | integer >= 1 | `1048576`（1 MiB） | ペインごとの生出力リング。attach の再生用。 |
| `rings.linesBytes` | integer >= 1 | `4194304`（4 MiB） | ペインごとの行リング。`pane.subscribe_lines` 用。文字数 + 1 行あたり 64 として数えます。 |
| `rings.events` | integer >= 1 | `1000` | デーモン全体のイベントリングに保持するイベント数。 |
| `socket` | string | [ソケットの場所](#ソケットの場所)を参照 | ソケットのパス（絶対パス、または `~/` で始まるパス）。 |
| `logLevel` | `"error"` \| `"warn"` \| `"info"` \| `"debug"` | `"info"` | デーモンのログしきい値（stderr に出力）。 |

`keys` の詳細:

- アクションキー（`detach`、`next`、`prev`、`list`）は `C-<char>` か、表示可能な ASCII 1 文字です。
  互いに、またプレフィックスとも異なっていなければなりません。
- 既定のプレフィックスが `Ctrl-^`（0x1E）なのは、一般的なフルスクリーンプログラムがこれに反応しないためです。
  Phase 0 の確認（vim、readline を使う bash、Claude Code、Codex）では、`Ctrl-^` はどれにも何の変化も起こしませんでしたが、
  `Ctrl-]` と `Ctrl-\` は vim の画面を変え、`Ctrl-_` は bash の挙動を変えました。
- プレフィックスを 2 回押すと、ペインにプレフィックスのバイトが 1 つ送られます。プレフィックスの後のそれ以外のキーは破棄されます。

## 検証

| 問題 | 結果 |
|---|---|
| 未知のキー（どの階層でも） | stderr に警告（`unknown key "<path>" ignored`）。そのキーは無視され、コマンドは実行されます。 |
| 型の誤り、または範囲外の値（例: `"scrollback": "5000"`、`"rings": {"events": 0}`） | エラー、終了コード `1`。デーモンは起動せず、コマンドも実行されません。 |
| 不正な JSON、読み取れないファイル、または存在しない明示パス | エラー、終了コード `1`。 |
| 不正な `keys`（コントロールキーでないプレフィックス、重複、プレフィックスとの衝突） | エラー、終了コード `1`。 |
| ソケットパスが長すぎる、または絶対パスでない | エラー、終了コード `1`。 |

ファイルに未知のキーと不正な値の両方がある場合は、不正な値が優先されます（エラー）。

## ソケットの場所

ソケットのパスは、次のうち最初に見つかったものです。

| 順序 | 取得元 |
|---|---|
| 1 | `$MISAO_SOCKET`（空は未設定として扱う） |
| 2 | `misao.json` の `socket` |
| 3 | `$MISAO_DIR/misao.sock` |
| 4 | `~/.misao/misao.sock` |

`misao serve --socket PATH` は、そのデーモンについてこれらすべてを上書きします（相対パスはカレントディレクトリを
基準に解決されます）。このパスはクライアントとデーモンの両方で同じように使われるため、
同じ環境とファイルを見ている限り、クライアントとデーモンは一致します。デーモンが起動したペインには、
環境変数 `MISAO_SOCKET` と `MISAO_PANE_ID` が渡されます。

制約:

- **長さ**: 最大 **107 バイト**（Linux の `sun_path` の上限で、NUL を含めて 108）。
  これより長いパスは、パスとその長さを示すエラーになります。`~/.misao` のような短いディレクトリを
  使うことをお勧めします。
- **絶対パス**: 値は絶対パスか `~/` で始まるパス（ホームディレクトリに展開されます）でなければなりません。
- **パーミッション**: 親ディレクトリはモード `700` で作成されます。既存のディレクトリは、現在のユーザーが所有し、
  シンボリックリンクではなく、グループ/その他のパーミッションが付いていない必要があります。
  そうでない場合、デーモンは起動を拒否します（実行すべき `chmod 700` を表示します）。ソケットファイルは
  モード `600` に設定されます。
- 古いソケット（誰も listen していないもの）は起動時に削除されます。別のデーモンがすでに
  listen している場合、`serve` は失敗します。
- `daemon.pid` と `persistence.json` はソケットの隣（ソケットのあるディレクトリ）に置かれます。`misao serve` で
  `--data DIR` を指定した場合は、そのディレクトリに置かれます。

## メモリの目安

各ペインは、生リング、行リング、そして `scrollback` 行を持つ画面モデル（`@xterm/headless`）を保持します。
デーモンはさらにイベントリングを 1 つ保持します。

| 項目 | 上限 | 目安 |
|---|---|---|
| 生リング（`rings.rawBytes`） | ペインあたり 1 MiB | 上限程度 |
| 行リング（`rings.linesBytes`） | ペインあたり 4 MiB | いっぱいになると**ペインあたりヒープ約 5 MiB** |
| イベントリング（`rings.events`） | 1000 件 | わずか |
| 画面モデル（`scrollback`） | ペインあたり 5000 行 | `scrollback` と画面幅に応じて増える。ここでは計測していません |

行リングの数値は計測値です（Node 24、gc 後のヒープ増加量、購読者なしでリングを満たした状態）。
60 文字の行（約 34,000 行）で約 5.2 MiB、空行（約 66,000 行）で 4.7 MiB でした。これらの数値は
**目安にすぎず**、環境によって異なります。予算を見積もるには、ペインあたりの数値に、動かし続ける
ペインの想定数を掛け、さらに画面モデルを足してください。

行リングは、購読者がどれだけ停滞すると追い越されて `gap: true` を通知されるかを決めます
（[プロトコル](protocol.ja.md#購読-pull-型とバックプレッシャー)を参照）。計測したマシンでは、4 MiB のリングは
1000 ラウンドのバーストテストを gap なしで耐えました。小さくするとメモリは節約できますが、
遅いコンシューマーでは gap がより早く発生します。

## サービスとして動かす

[deploy/README.md](../deploy/README.md) は、systemd のユーザーユニットでデーモンを動かすための
正式なガイドです（インストール、linger、クリーンアップ、Node が `PATH` にない場合、アンインストール）。要点は次のとおりです。

- `deploy/misao.service` は `Restart=on-failure` と `RestartSec=1` で `misao serve` を実行します。
- `KillMode=process`: 停止時、systemd はデーモンにだけシグナルを送り、デーモンがすべてのペインを
  自分で閉じるため、ペインの終了処理で systemd とデーモンが競合しません。クラッシュ後、systemd は
  cgroup 内のプロセスに手を出さないので、エージェントは再起動後に生き残りません。
- 再起動後、ペインは生きた PTY としては復元されません。メタデータは保持され、`stopped` として表示されます
  （[プロトコル](protocol.ja.md#ペインのライフサイクルと永続化)を参照）。
- ログアウト後もデーモンを動かし続けるには、`loginctl enable-linger "$USER"` を一度実行してください。
