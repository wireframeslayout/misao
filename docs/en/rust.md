# Rust implementation

[English](../en/rust.md) | [日本語](../ja/rust.md)

misao's daemon and CLI are being rewritten in Rust as a single `misao` binary, distributed through
GitHub Releases. The SDK (`@misao/sdk`) and the protocol (`@misao/protocol`, `PROTOCOL_VERSION`
0.3.0) stay in TypeScript and the protocol does not change. Until the Rust build passes the whole
existing e2e suite (`packages/e2e`), the Node build is the official one.

Related documents: [Protocol](../protocol.md), [CLI](../cli.md), [Configuration](../config.md).

## Layout

```text
Cargo.toml              workspace (resolver 3, edition 2024, MSRV 1.88, shared lints)
rustfmt.toml  clippy.toml  deny.toml
crates/
  misao-protocol/       wire types: JSON-RPC, ErrorCode, ServerInfo, NDJSON framing
    schema/protocol.json  JSON Schema exported from the Zod schemas (generated, committed)
    tests/schema_conformance.rs
  misao-daemon/         daemon core: socket, pid file, logger, accept loop, dispatch
  misao/                the binary: clap CLI (`serve`, `--version`), config, socket path
```

Dependencies point one way: `misao` -> `misao-daemon` -> `misao-protocol`.

## Build and test

```bash
cargo build --workspace            # target/debug/misao
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
cargo deny check                   # licenses, advisories, sources (see deny.toml)
```

Policy: stable Rust, MSRV `1.88` (`workspace.package.rust-version`, checked in CI by the `Rust (MSRV)` job),
`unsafe_code = "forbid"`, clippy `all` denied, and `unwrap` / `expect` denied outside tests.
`Cargo.lock` is committed and CI uses `--locked`.

Run the Rust daemon by hand:

```bash
target/debug/misao serve --socket /tmp/misao-try/misao.sock --data /tmp/misao-try
```

## Node and Rust correspondence

| Node (`packages/`) | Rust (`crates/`) | Stage 1 status |
|---|---|---|
| `protocol` (Zod schemas, `ErrorCode`, framing) | `misao-protocol` | types for `server.info`, JSON-RPC, errors, NDJSON; checked against the schema |
| `daemon/src/socket.ts` | `misao-daemon/src/socket.rs` | done (dir 700 / socket 600, owner and symlink checks, stale socket) |
| `daemon/src/pid-file.ts` | `misao-daemon/src/pid_file.rs` | done |
| `daemon/src/daemon.ts` (`start` / `shutdown` / dispatch) | `misao-daemon/src/daemon.rs` | `server.info`, `server.schema` only; other known methods return `NotImplemented` |
| `daemon/src/log.ts` | `misao-daemon/src/log.rs` | done (`[misao <ISO time>] msg` on stderr) |
| `sdk-node/src/socket-path.ts` | `misao/src/socket_path.rs` | done (same priority and the 107-byte limit) |
| `cli/src/config/*` | `misao/src/config.rs` | `socket` and `logLevel` are used; `keys` / `scrollback` / `rings` are only type-checked |
| `cli` `serve`, `--version` | `misao/src/{cli,serve}.rs` | done; other commands come in later stages |
| pane / screen / state tracking / persistence | - | not started (stages 2-4) |

Intentional differences in stage 1: the `--help` text is generated by clap (Japanese about text, English
flag names); `--version` prints `misao <Cargo version>`, which is `0.0.0` until the release scripts
learn to set it (stage 6); on Windows `misao serve` exits with an error because the connection endpoint
is a later stage (see `docs/*/windows.md`).

## Protocol conformance

`node scripts/export-protocol-schema.mjs` (needs `npm run build`) writes
`buildProtocolJsonSchema()` of `@misao/protocol` to `crates/misao-protocol/schema/protocol.json`.
The file is committed, so `cargo test` needs no Node.

- `packages/protocol/test/rust-schema-sync.test.ts` fails when the committed file is out of date
  (run as part of `npm test`). Change a Zod schema, regenerate, commit.
- `crates/misao-protocol/tests/schema_conformance.rs` checks that the protocol version, method and
  notification names, error codes, the `server.info` fields (names and required-ness), and JSON-RPC
  responses produced by the Rust types satisfy the exported schema.
- `server.schema` in the Rust daemon returns the embedded `schema/protocol.json`.

## Startup exclusion (difference from the Node build)

The Rust daemon takes an exclusive `flock` on `<socket>.lock` (next to the socket, independent of
`--data`) from the stale-socket check until `bind` finishes, so two concurrent starts cannot remove each
other's socket. A failed `bind` never deletes the path; only a socket whose `chmod` failed after our own
`bind` is removed. The lock file itself is left in place on purpose. The Node daemon does not have this
lock: its check-then-unlink-then-listen sequence can race when two daemons start at the same moment
with different pid-file locations. It is not fixed in the Node build (it is replaced instead).

## Running the e2e suite against the Rust daemon

`packages/e2e/test/helpers/daemon-process.ts` starts the daemon with `misao serve --config ... --socket ...
--data ...`. Set `MISAO_DAEMON_BIN` to run another implementation instead of the Node CLI:

```bash
cargo build -p misao
MISAO_DAEMON_BIN=$PWD/target/debug/misao npm run test:e2e -w @misao/e2e   # whole suite
npm run test:e2e:rust -w @misao/e2e                                       # the part that passes (CI)
```

Without the variable nothing changes. Status at stage 1:

| Test file | Rust daemon |
|---|---|
| `server-info.test.ts` | passes |
| `v2-attach-replay`, `v2-size-conflict`, `v3-line-markers`, `v4-hub-restart`, `v5-catch-up`, `v5-key-collisions` | fail with `not implemented: pane.open` (panes are stage 2) |
| `v2-claude`, `v4-systemd` | opt-in; skipped |
